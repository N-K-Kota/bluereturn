# 設計・実装レビュー（2026-09-15）

## 主な問題と修正

| 領域 | 問題 | 修正 |
| --- | --- | --- |
| 保存 | JSから別々のプール接続にBEGIN・INSERT・COMMITが送られ得る | Rustのトランザクションが一つの接続を保持。CSV辞書登録も同一トランザクションに含める |
| 入力 | 空仕訳、負数・小数、片側のない明細が保存可能 | JSとRustで日付・整数円・借貸一致を検証 |
| 初期化 | 一度失敗すると再試行不可、マイグレーションのエラーを全て無視 | 失敗したPromiseを解放。存在する列を調べ、必要なALTERのみ実行 |
| 集計 | BSが累積残高に当期利益だけを加算 | 前期以前の未振替損益と当期利益を分離。振替済み利益は二重計上しない |
| 申告 | 事業の雑収入・営業外費用を集計から除外 | P&Lの純利益と申告の控除前所得を整合 |
| 税計算 | 2024・2025年に同じ控除表を使用 | 年度別の基礎控除と給与所得表に分離、境界値をテスト |
| 控除 | 生命保険の合計が12万円超、赤字時に医療費控除が発生 | 合計上限・負の所得・端数処理を修正 |
| 税額 | 定額減税・給与以外の源泉税・予定納税が未反映 | 入力欄と保存列を追加。納付と還付の端数処理を分離 |
| 消費税 | 合計税率10%に地方税を追加して過大計算 | 国税7.8%と地方税を分離。税込入力の簡易課税を割り戻す |
| 画面間整合 | 保存済み売上0が印刷時に帳簿売上へ置換 | 共通のcalculateReturnを使用し、明示的な0を維持 |
| 非同期処理 | 年度・期間変更前の結果が上書き、読み込み失敗が非表示 | 年度別フォームの分離、古い読み込みの破棄、失敗表示・再試行 |
| CSV | 引用符内の改行、返金、方向の異なる辞書ルールに誤対応 | CSV構文解析、日付正規化、返金の反転、入出金別の最長キーワード照合 |
| 辞書 | 編集時に削除してから再挿入するため失敗すると消失 | 単一UPDATEに変更。重複時は元のルールを維持 |
| 印刷・配布 | useSearchParamsの静的生成境界がない、固定レイアウトの印刷、外部フォント依存 | Suspense、印刷用CSS、OS標準フォント |

## 検証

- TypeScript回帰テスト：税額・控除の境界値、損益とBS、CSVと文字コード、日付・仕訳検証。
- Rust/SQLite：途中の仕訳失敗・辞書登録失敗時の全件ロールバック、成功時の全件保存、削除の参照整合性。
- 型チェック、ESLint、本番の静的エクスポート。
- デスクトップ開発版の起動とページ応答。

自動テストはGUI操作全体や税制の全適用条件を保証しません。計算対象外の項目はREADMEと画面の「計算の対象」に明記しています。

## 手動確認の観点

- 年度を素早く切り替え、前年度の納税者情報・入力値が混在しないこと。
- 入力を保存後、結果から戻って修正・再計算できること。
- 消費税の売上0・2割特例が、結果・ガイド・印刷で一致すること。
- CSVの選択行の科目未指定や保存失敗時に、仕訳・辞書が一部だけ残らないこと。
- 使用中の科目の削除や、重複キーワードへの辞書編集でエラーが表示されること。
- 複数ページの印刷でサイドバーが出ず、本文が欠けないこと。
